## 🎯 具体的に何ができるの？

### 1️⃣ 募集要件を読み解く（JD 分析）

求人情報（JD）を貼り付けると、次のことを分解してくれます：
- このポジションが**実際に何を求めているか**（字面だけではない本質）
- **ハードスキル**（必須の技術・ツール）と**ソフトスキル**（コミュニケーション、チームワークなど）
- **暗黙の条件**——JD には書かれていないが、人事が頭の中で持っている要件

### 2️⃣ あなたの経験とポジションを照合する（ギャップ診断）

履歴書を渡すと、要件ごとに照らし合わせてくれます：
- ✅ **強い根拠**：あなたの経験がこの要件にまさに合致している
- ⚠️ **弱い根拠**：関連はあるが書き方が物足りない
- ❌ **ギャップ**：この要件にはまだ材料がなく、何を補う必要があるか

### 3️⃣ 思い出していない重要な材料を掘り下げる

やったこともないことを勝手に作るのではなく、次のような非常に具体的な質問をしてきます：
> 「サークルで広報を担当したそうですが、具体的にどんなツールを使いましたか？イベントは何回開催しましたか？何人の人に届きましたか？」
> 「この授業プロジェクトの final score はいくつですか？誰と一緒にやり遂げましたか？」

こうした詳細があって初めて、履歴書に説得力が生まれます。

### 4️⃣ 履歴書の内容を書き直す（bullet 最適化）

もともとの味気ない記述（例：「公式アカウントの運営を担当」）を、次のように変えてくれます：
> 📝 **「大学の公式アカウントを独自に運営し、6 か月で 40 本以上の記事を公開。単一記事の最高閲覧数 3.2 万、フォロワー数は 1,200 人増加。」**

### 5️⃣ カバーレター・応募メール・推薦依頼メッセージの作成を支援

- 🎯 **Cover Letter**（カバーレター）
- 📧 **応募メール**（選考応募用）
- 💬 **LinkedIn / WeChat のダイレクトメッセージ**（推薦を依頼するときに使用）

### 6️⃣ 面接対策

履歴書のすべての項目を**面接官が聞きそうな質問＋どう答えるべきかのアウトライン**に変換し、面接で焦らずに済むようにします。

### 7️⃣ 見栄えの良い履歴書 PDF を生成（オプション）

最終版が必要な場合は、最適化した内容を**プロフェッショナルで明快、人事が見やすい** PDF 履歴書にレイアウトしてくれます。次の 3 つのスタイルに対応：

| スタイル | 向いているポジション |
| :--- | :--- |
| `Classic Professional` | 金融、コンサルティング、法律、官公庁、国営企業、教育、会計、監査 |
| `Modern Minimal` | **デフォルトスタイル**——テクノロジー、データ、AI、プロダクト、インターネット、スタートアップ |
| `Creative Clean` | マーケティング、コンテンツ、メディア、ブランド、デザイン、ソーシャルメディア運営 |

## 🔧 あなたの AI にインストール（一行コマンド）

Skill をサポートする AI アシスタント（例：Claude Code、Codex CLI、OpenCode、Hermes Agent）が必要です。そこに Easy-Job-Tutor をインストールします。

> 🖥️ **コマンドライン（ターミナル）に詳しくない場合は、この手順をプログラマーの友人にコピーして渡すか、AI ツールに「Easy-Job-Tutor のインストール方法を教えて」と聞いてみてください。AI が一歩ずつ教えてくれます。**

### ワンクリックインストール

お使いの OS に合わせて、対応する一行コマンドをコピー＆ペーストするだけです。**仮想環境の作成 → 依存関係のインストール（PDF 書き出し含む）→ インストール済みの AI ツールの検出とセットアップ**が自動で完了します。

**macOS / Linux**

```bash
git clone https://github.com/yicLionel/Easy-Job-Tutor.git && cd Easy-Job-Tutor && python3 install.py
```

**Windows（PowerShell）**

```powershell
git clone https://github.com/yicLionel/Easy-Job-Tutor.git; cd Easy-Job-Tutor; py install.py
```

> 💡 **オプション引数**：今は PDF 書き出しが不要なら `--skip-pdf` を追加。AI ツールへの自動インストールを希望しない場合は `--skip-tools` を追加。スクリプトがツールを検出できなかった場合は、`--tool codex / claude / opencode / hermes` で強制的に指定できます。
> 🔔 依存関係のインストールでエラーが出ても慌てないでください——**主要機能（JD 分析、履歴書の最適化、面接対策）はそれがなくても使えます**。PDF 書き出しはオプションです。

> インストールが完了すれば、あなたの AI アシスタントはこのスキルを身につけます！

## 🚀 クイックスタート

### 使い方——AI にこう伝えるだけ：

> 💡 **呼び出し方は 2 通り**：プロンプトに「Easy-Job-Tutor を使って」と書くか、AI ツールがスラッシュコマンドに対応していれば `/easy-job-tutor` と入力するだけでも呼び出せます。

応募予定の**求人情報（JD）**と**現在の履歴書**を AI に渡して、そのままこう伝えましょう：

> **「Easy-Job-Tutor を使って、このポジションを分析して、私の履歴書を最適化してください。経験を捏造しないで、足りない重要な情報があればまず私に聞いてください。」**

AI が次のフルプロセスを一歩ずつ進めてくれます：
1. ✅ まず募集要件を分析
2. ✅ 次にあなたの経験と照合してギャップを診断
3. ✅ 不足している重要な情報を質問
4. ✅ 履歴書の内容を書き直す
5. ✅ （オプション）PDF を生成

### 一部だけを依頼する場合も、こう言えばOK：

| やりたいこと | AI への伝え方 |
| :--- | :--- |
| ポジションの分析だけ | 「Easy-Job-Tutor でこの JD を分析して、このポジションが本当に重視していることを教えて」 |
| 履歴書の修正だけ | 「この JD を参考に、履歴書の職歴をもっとプロフェッショナルに直して」 |
| Cover Letter 作成 | 「このポジション向けにカバーレターを書いて」 |
| 面接対策 | 「最適化後の履歴書に基づいて、面接で聞かれそうな質問を準備して」 |
| PDF 生成 | 「履歴書を PDF にして、Modern Minimal スタイルでお願い」 |

## 💬 参考例：本当の経験を AI に渡す

以下はすべて架空の例で、材料の渡し方を説明するためのものです。実際に使うときは、自分で説明できて裏付けが取れる経験だけを記入してください。分からないデータは「要確認」と書き、AI に推測や補完をさせないでください。

### 例 1：インターン経験がなくても、データ分析のインターンに応募する

授業プロジェクト、サークル活動の経験、JD をまとめて AI に送ります：

```text
Easy-Job-Tutor を使って、データ分析インターン用の履歴書を準備してください。

対象 JD：
- SQL、Python、Excel に精通し、データクレンジングと基礎的な分析ができること；
- 可視化やビジネス分析のプロジェクト経験がある方を優先；
- プロダクトや運営チームと協力し、結論を明確に報告できること。

私の実際の経験：
- クラスメート 3 名と学内の出前アンケート分析の授業プロジェクトを実施；
- 私が Python で有効回答 1,200 件をクレンジングし、Excel でグラフを作成；
- 最終的に 12 ページの分析レポートと授業での発表を完了；
- 実際の A/B テストは実施したことがなく、レポートが業務で採用されたかも不明。

最初に、JD の要件と私の経験の対応表と、最も補うべき 5 つの質問を出力してください。
そのうえで、確認済みの事実のみに基づいて履歴書の bullet を書いてください。
授業プロジェクトを会社のインターンとして書かないでください。
```

こうすることで、「宿題をやっただけ」を無理やり「実務経験がある」と飾るのではなく、質問されても答えられるプロジェクト表現が得られます。

### 例 2：運営から AI プロダクトマネージャーへキャリアチェンジ

転職で最も大切なのは、直接経験・転用可能な能力・本当のギャップを区別することです：

```text
運営から AI プロダクトマネージャーへの転向を検討しています。
Easy-Job-Tutor でまずギャップ診断を行ってください。最終版の履歴書を直接書かないでください。

対象 JD：
- AI プロダクトの要件調査、PRD、プロトタイプ、リリース後の振り返りを担当；
- 大規模言語モデル、RAG、Agent の典型的な適用範囲を理解していること；
- 開発、デザイン、ビジネスチームの連携を推進できること。

確認済みの経験：
- 企業研修イベントの要件収集、スケジュール調整、部門間コミュニケーションを担当；
- 社内ナレッジベースの Q&A デモを独学で作成したが、リリースはしておらず実ユーザーのデータもない；
- 機能説明書とテストチェックリストを書いたことがあるが、PRD を単独で一任されたことはない。

内容を「直接の根拠」「転用可能な能力」「学習・作品の根拠」「本当のギャップ」に分けてください。
さらに、「担当」や「推進」といった動詞を使うために、あとどのような事実を補う必要があるか教えてください。
```

目的は AI 関連のキーワードを並べることではなく、誠実で実行可能な証拠の補充計画を得ることです。

### 例 3：同じ経験を複数のポジションに応募する

プロダクト・運営・グロースのキーワードを混ぜて万能な履歴書にしないでください。まず共通の事実の下書きを作り、そのうえでバージョンごとに生成します：

```text
同じ実際の経験の下書きに基づいて、「プロダクト運営」と「ユーザーグロース」の 2 つの独立したバージョンを生成してください。

事実の下書き：
- 学内サークルでイベント申し込みフローの改善を担当；
- 申し込み者 15 名にインタビューし、頻出の問題を 4 つ整理；
- デザイン担当の学生と一緒に申し込みフォームとリマインド文言を修正；
- イベントの申し込み人数が前回の 86 人から 124 人に増加；
- 増加が完全にフォームの改修によるものかは確認できていない。

ポジション A：プロダクト運営 JD：[JD を貼り付け]
ポジション B：ユーザーグロース JD：[JD を貼り付け]

最初に 2 つのポジションの証拠マッピングとバージョン間の差異表を出力し、そのうえでそれぞれの履歴書 bullet を書いてください。
チームの成果をすべて私の功績にしないでください。因果関係が確認できないデータには慎重な表現を使ってください。
```

内容が確認できたら、「Modern Minimal スタイルで A4 1 ページの PDF を生成し、内容のはみ出し、空白ページ、プレースホルダーを確認してください」と一言添えれば、レイアウトと書き出しの段階に進めます。

## ⚠️ 重要な注意点

- ✅ **捏造しない**：学歴、会社、プロジェクト経験、データ、受賞歴を勝手に作ることはありません
- ✅ **先に確認してから書く**：根拠のない内容は先にあなたに確認し、いきなり履歴書に書き込むことはありません
- ✅ **HR のために設計**：キーワードを並べるのではなく、人事が一目でマッチ度を判断できることを優先します
- ✅ **誠実さ第一**：あなたの履歴書は、面接で必ず突っ込まれても答えられるものになります
